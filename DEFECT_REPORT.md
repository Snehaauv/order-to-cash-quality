## Findings in detail

### D-01 - ORD-1006 - Every non-Cart order must reach Analytics

**Severity** Critical | **Dimension** completeness | **Rule** `COM-001`

Order is Delivered in the OMS but has no events at all in Analytics - the order is invisible to every downstream metric.

**Contract clause violated**  
> Carts do not sync. Every order in any state other than Cart must have at least an Order Placed event in Analytics.

**How it was detected**  
Left anti-join orders -> event log on OrderId = CaseId, excluding Status = Cart.

**Evidence**
```
  omsStatus: Delivered
  omsAmount: 15600.00
  omsCurrency: USD
  analyticsEventCount: 0
```

### D-02 - ORD-1010 - Delivered event timestamp must equal the OMS DeliveredDate

**Severity** Critical | **Dimension** temporal correctness | **Rule** `TMP-002`

Delivered event is 2026-08-20T09:00:00Z but the OMS records delivery at 2026-08-24T12:00:00Z - which is exactly the timestamp carried by "Order Shipped". The two activities appear to have been transposed during sync.

**Contract clause violated**  
> All timestamps are stored in UTC.

**How it was detected**  
Compare the Order Delivered event against DeliveredDate, then classify the delta against real UTC offsets to separate a timezone fault from independent clock skew.

**Evidence**
```
  omsDeliveredDate: 2026-08-24T12:00:00Z
  analyticsDeliveredAt: 2026-08-20T09:00:00Z
  delta: -99:00
  deltaKind: whole-hour-shift
  hypothesis: delta is a whole number of hours (-99:00) but does not map to a common zone - check for a hard-coded offset or a daylight-saving transition
  transposedWith: Order Shipped
```

### D-03 - ORD-1007 - Event amount must equal the source order amount

**Severity** Critical | **Dimension** value correctness | **Rule** `VAL-001`

"Order Delivered" carries 1234.60 but the order is 1234.56 - a 0.04 discrepancy on a single event, so the case reconciles differently depending on which event a report reads.

**Contract clause violated**  
> Amount and currency on every Analytics event must match the source order exactly.

**How it was detected**  
Per-event comparison in integer minor units (see src/domain/money.js) - no float tolerance.

**Evidence**
```
  activity: Order Delivered
  omsAmount: 1234.56
  analyticsAmount: 1234.60
  differenceMinorUnits: 4
  eventLine: 22
```

### D-13 - ORD-1010 - Happy-path events must be non-decreasing in time

**Severity** Medium | **Dimension** temporal correctness | **Rule** `TMP-003`

"Order Delivered" (2026-08-20T09:00:00Z) precedes "Order Shipped" (2026-08-24T12:00:00Z) even though it comes later in the happy path. Any duration measured between these two steps is negative.

**Contract clause violated**  
> For a given order, event timestamps must be non-decreasing in happy-path order.

**How it was detected**  
Rank each happy-path activity, then assert timestamps rise with rank. Independent of the conformance replay, which reads the trace order rather than the clock.

**Evidence**
```
  earlierInPath: Order Shipped
  earlierTimestamp: 2026-08-24T12:00:00Z
  laterInPath: Order Delivered
  laterTimestamp: 2026-08-20T09:00:00Z
  negativeDurationOf: 4d 3h
```
